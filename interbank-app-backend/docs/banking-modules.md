# Módulos bancarios adicionales (simulación académica)

La API usa la misma sesión JWT/Redis del backend móvil, DTO validados, repositorios Prisma y esquema PostgreSQL `app`. Ningún endpoint de este documento mueve dinero fuera de la base de datos de pruebas ni se conecta a la red real de Plin/Yape.

## Rutas

| Módulo      | Rutas                                                                                                                                                                                                                                                       | Alcance                                                                                                                                                                                                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Perfil      | `GET/PATCH /profile`, `GET/PATCH /profile/details`, `GET/POST /profile/addresses`, `PUT/DELETE /profile/addresses/:id`                                                                                                                                      | Datos propios, nombre, preferencia comercial, detalles y direcciones separadas. DNI y correo no son editables por esta ruta.                                                                                                                                                         |
| Celular     | `POST /profile/phone/challenge`, `POST /profile/phone/verify`                                                                                                                                                                                               | Código con vencimiento de 5 minutos y máximo 5 intentos. En desarrollo se devuelve `demoCode` para pruebas. En producción se bloquea hasta integrar un proveedor SMS.                                                                                                                |
| Plin        | `GET/POST/DELETE /plin/enrollment`, `GET /plin/sources`, `GET /plin/networks`, `POST /plin/recipients/resolve`, `GET/POST /plin/favorites`, `DELETE /plin/favorites/:phoneNumber`, `GET /plin/recents`, `GET/POST /plin/payments`, `GET /plin/payments/:id` | Solo cuentas propias verificadas en PEN y destinatarios internos afiliados. S/1–500 por envío, S/2,000 diarios (día de Lima), sin autotransferencias. Débito, crédito, movimientos y comprobante se crean en una sola transacción SQL. Los POST de pago requieren `Idempotency-Key`. |
| Préstamos   | `GET /loans/offers`, `POST /loans/quote`, `GET/POST /loans/applications`, `GET /loans/applications/:id`, `GET /loans/applications/:id/schedule`, `POST /loans/applications/:id/cancel`                                                                      | Cotización ilustrativa con TEA fija de prueba y cronograma. Solicitud persistente e idempotente en `PENDING_REVIEW`; no existe aprobación ni desembolso automático.                                                                                                                  |
| Promociones | `GET /promotions/categories`, `GET /promotions`, `GET /promotions/saved`, `GET /promotions/:id`, `POST/DELETE /promotions/:id/save`, `GET /promotions/vouchers`, `GET /promotions/vouchers/:id`, `POST /promotions/:id/vouchers`                            | Catálogo, comercios, favoritos y códigos de demostración individuales, con emisión idempotente. La semilla genera únicamente campañas ficticias claramente identificadas.                                                                                                            |

En Swagger se muestran los nuevos controladores. Todas las rutas requieren JWT válido. La validación de celular demo **no acredita propiedad real del número**; antes de producción hacen falta SMS con entrega externa, políticas antifraude, auditoría, consentimiento, revisión de seguridad y pruebas de carga. La interoperabilidad con Yape y la red Plin requiere convenio/API oficial; no se simula como si fuese una transferencia interbancaria efectiva.

La app puede presentar la marca Yape en un destinatario cuando la persona **elige** Yape como red. `logoKey: "YAPE"` sirve para que el cliente seleccione un recurso gráfico local; no acredita que el número pertenezca a Yape. `verified: false` y `available: false` indican que esta API no dispone de consulta de titularidad ni liquidación interoperable. Se rechaza un envío a Yape **antes del débito**. Recibir desde Yape también requiere eventos firmados y conciliados de un operador autorizado; un cliente móvil no puede declarar unilateralmente un abono. Los envíos internos de prueba incluyen `simulated: true` en la respuesta para que ninguna integración los confunda con dinero real.

La base ahora separa perfil extendido y direcciones, contactos favoritos de Plin, comercios de promociones y códigos emitidos por usuario. No se creó una cantidad artificial de tablas: cada entidad tiene responsabilidad, claves foráneas, índices y restricciones propias. Esto **no es un core bancario completo**; KYC, prevención de fraude, compensación externa, contabilidad, conciliación y canje comercial requieren sistemas y acuerdos adicionales. Los códigos de esta API son demostrativos (`redeemableExternally: false`) y no funcionan en cines o restaurantes reales.

## Flujo de prueba

1. Inicia sesión en `/auth/login` y usa el `accessToken` como `Bearer` en Swagger.
2. Consulta `/profile`; en `NODE_ENV=development`, solicita `POST /profile/phone/challenge` con `{ "phoneNumber": "987654321" }` y verifica el `demoCode` mediante `POST /profile/phone/verify` con `{ "code": "123456" }`. El código concreto cambia en cada solicitud.
3. Usa `GET /plin/sources` y afilia una cuenta de soles con `POST /plin/enrollment` (`{ "accountId": "UUID" }`). Para probar un envío se necesita **otro usuario demo** afiliado con otro celular. Resuelve su número en `/plin/recipients/resolve`; luego envía `{ "fromAccountId": "UUID", "phoneNumber": "9XXXXXXXX", "amount": 10.50 }` a `/plin/payments` con `Idempotency-Key` nueva. Reintentar con la misma clave devuelve el comprobante, no duplica el débito. El celular debe pertenecer al propio usuario al afiliarse; no basta con escribir un número cualquiera.
4. Obtén las condiciones ilustrativas en `/loans/offers`, solicita una cotización con `{ "principal": 10000, "months": 12 }` en `/loans/quote`, y si corresponde registra `{ "principal": 10000, "months": 12, "destinationAccountId": "UUID" }` en `/loans/applications` con `Idempotency-Key`. Solo se guarda la solicitud; no se abona dinero.
5. Revisa `/promotions` y `/promotions/:id` para las campañas demo, guarda una con `POST /promotions/:id/save` y emite un código de prueba en `POST /promotions/:id/vouchers`. El mismo usuario recibe el mismo código si reintenta; consulta su billetera en `GET /promotions/vouchers`.
6. Consulta `/plin/networks` y guarda un destinatario en `/plin/favorites`; `/plin/recents` deriva los números del historial de pagos. Seleccionar `network: "YAPE"` en `/plin/recipients/resolve` permite mostrar la red elegida, pero intentar enviar devuelve servicio no disponible sin mover saldo.

Para instalar el esquema en otra copia: `pnpm prisma:generate`, `pnpm prisma:migrate`, `pnpm prisma:seed:promotions`. El servicio que ya corre en Docker necesita reconstruir su imagen para exponer el código nuevo; `Ctrl+S` no actualiza un contenedor construido previamente.

La simulación de préstamo no debe mostrar su TEA como TCEA: excluye seguro y gastos. La SBS indica que el cronograma y costo total de un crédito real deben incluir esos conceptos. Las promociones de prueba no son ofertas comerciales canjeables.
